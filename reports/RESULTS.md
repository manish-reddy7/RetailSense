# RetailSense — Final Results

Single frozen run on the **test split** (d_1886–d_1941, 4 Mar – 28 Apr 2024), store MUM_1,
60 items, 3,360 forecast points at h = 1, plus three rolling-origin backtests. Data: India kirana
chain generated by `retailsense.data.india_generator` (fixed seed) with real Open-Meteo weather and
the real Indian festival calendar.

| Prompt | v1, frozen 2026-10-01 |
| LLM | `llama3.1:latest` (8B) via local Ollama, temperature 0, seed 42, 4 parallel workers |
| Config hash | `acbb90af8345` (`reports/india/final/RUN_LOCK.json`) |
| MLflow | experiment `india_phase5`, run `14e1f0e0999f451897d3e61011a56d49` |
| Sources | `reports/india/final/table_*.csv`, `case_study.json`, `reports/figures/india/final/*.png` |

Every number below is copied from those files. Differences are RetailSense minus the other
system, so a negative WAPE difference means RetailSense is more accurate. CIs are 95 % paired
bootstraps over items (1,000 resamples).

## Headline

- **The single LightGBM with all features is the most accurate system** on test (h1 WAPE 0.3688)
  and in all three backtests. RetailSense is significantly less accurate than it (+0.0087
  [0.0015, 0.0161], DM p = 0.003).
- **ETS has the lowest inventory cost** ($138,621 vs RetailSense $206,313; RetailSense costs
  $1,128 more per item [220, 2,211]).
- **Deliberation helps a little where it triggers** (H2, Wilcoxon p = 0.007), but the effect on
  overall accuracy is about 0.02 WAPE points, and **D is no better than a random trigger** (H4).
- RetailSense matches always-on deliberation at **73 % fewer LLM calls** (H3).

## Hypotheses

### H1 — Does disagreement predict error? **Weakly supported.**
- Test: Spearman ρ(D, relative error) = 0.072 [0.039, 0.108]; AUROC of D for the worst 20 %
  of errors = 0.539 [0.505, 0.565] (`table_mechanism.csv`).
- Backtests: ρ = 0.041 / 0.036 / 0.052 and AUROC = 0.526 / 0.512 / 0.516.
- Both CIs exclude chance on test, but the signal is small: 0.5 is chance and the backtest AUROCs
  are close to it. Validation gave the same picture (ρ 0.064, AUROC 0.535), where D added nothing
  beyond the Historical band width and item volume.

### H2 — Does deliberation improve the triggered cases? **Supported, small effect.**
- 892 triggered points (trigger rate 26.5 %, inside the 10–30 % gate); fallback rate 0 %.
- 30.3 % improved, 24.6 % worsened; mean absolute error 12.661 → 12.633; Wilcoxon p = 0.007.
- Hold rate 58.7 %, so agents were not simply complying with the critic.
- On validation the same comparison was not significant (33.7 % improved vs 29.3 % worsened,
  p = 0.32), so this effect should be read as small and not yet replicated.

### H3 — Selective vs always-on. **Supported on accuracy and cost; not on inventory.**
- WAPE difference vs always-on +0.0002 [−0.0003, 0.0008], DM p = 0.58: no detectable difference.
- LLM calls per 1,000 forecasts: 1,331 vs 5,018 (−73 %). Tokens per 1,000: 919k in / 152k out vs
  3,481k / 582k. Mean latency per forecast 6.9 s vs 20.7 s (`table_latency_llm.csv`; latency
  includes queueing behind 4 parallel workers).
- Inventory: always-on is cheaper ($199,868 vs $206,313), but the per-item cost difference
  (+$107 [−6, 266]) is not significant.

### H4 — Disagreement vs random trigger at the same rate. **Not supported.**
- Test WAPE difference −0.0003 [−0.0006, −0.00001]: the bootstrap CI only just excludes zero,
  while DM p = 0.08 and the item-level Wilcoxon p = 0.07.
- Inventory cost difference −$1.3 per item [−23, 20]: no difference.
- Backtests: the random trigger has lower WAPE than RetailSense in all three windows.
- Cost–accuracy curve (`table_cost_accuracy.csv`): selective is about two random-draw SDs better
  at trigger rates 0.1–0.2 (e.g. 0.37751 vs 0.37768, sd 0.00008 at 0.1) but worse than random at
  0.4–0.8. There is no consistent advantage.

### H5 — Do better forecasts give better inventory outcomes? **Not supported for RetailSense.**
Total test cost (`table_inventory.csv`): ETS $138,621, LightGBM all features $183,250, seasonal
naive $199,786, always-on $199,868, multi-agent mean $203,357, multi-agent confidence $205,862,
RetailSense $206,313, random trigger $206,393, Historical $232,910.

- ETS is significantly cheaper than RetailSense (+$1,128 per item [220, 2,211]).
- The most accurate system (LightGBM all features) is not the cheapest. Lower WAPE does not by
  itself lower cost here. The policy also depends on the bands, and lost-sales cost dominates
  the differences: $63,722 for ETS vs $136,574 for RetailSense.
- Lead time (`table_lead_time.csv`): ETS is cheapest at L = 1 and 3; at L = 7 seasonal naive is
  cheapest ($249,090) and RetailSense is the cheapest multi-agent system ($326,630).

## Ablations (test, `table_ablations.csv`)

| Ablation | Variant | Trigger rate | h1 WAPE | AUROC |
|---|---|---|---|---|
| — | No deliberation | 0 | 0.37772 | – |
| τ | Calibrated (q0.80 of validation D) | 26.5 % | 0.37752 | 0.539 |
| τ | Fixed τ = 0.3 | 0.3 % | 0.37772 | 0.539 |
| Normalisation | D_range | 26.3 % | 0.37756 | 0.542 |
| Normalisation | D_std (unnormalised) | 26.3 % | 0.37759 | 0.465 |
| Revision | Weights only (no revised values) | 26.5 % | 0.37768 | – |
| Drop agent | Without Calendar (fast path) | 29.3 % | 0.38199 | 0.543 |
| Drop agent | Without Trend (fast path) | 26.7 % | 0.37650 | 0.524 |
| Drop agent | Without Weather (fast path) | 21.3 % | 0.37552 | 0.531 |
| Weather noise | sd 1.0 (fast path) | 36.5 % | 0.37797 | 0.537 |

- An uncalibrated τ = 0.3 almost never triggers, so calibration matters for the trigger rate.
- Normalising D matters: the unnormalised spread has AUROC below chance (0.465).
- Revised values add a little over re-weighting alone (0.37752 vs 0.37768).
- **The Weather and Trend agents hurt accuracy:** removing either lowers WAPE. This matches the
  Phase 2 finding that the residual agents apply about the same adjustment to every item,
  because they have no item identity. Calendar is the only context agent that helps.
- Noisy weather raises the trigger rate from 26.5 % to 36.5 %; only 64 % of the triggered set
  stays the same (Jaccard 0.64).

## Case study (`case_study.json`, chosen by rule: the highest-D triggered point)
Item sevai_2 on d_1907 (D = 0.602): consensus 3.35, actual 2.0, final 3.35. The critic's main
conflict was generic ("the agents use different types of evidence"), and the revisions left the
consensus unchanged. This is typical of the 8B local model: the critic rarely identifies which
specific evidence is wrong.

## Limitations
- The sales are generated by a simulator with known drivers, so these results describe the
  method's behaviour when the true drivers are known, not a real store's performance.
- Weather is observed weather used as a perfect forecast; the noise ablation is the only check.
- One LLM (an 8B local model). A stronger critic might change H2–H4.
- One seed for the LightGBM models; no multi-seed evidence, so differences below about 0.001
  WAPE should not be over-read.
- Latency includes queueing behind 4 parallel workers on one laptop GPU.
- The context agents cannot route signals to the items they affect (no item identity), which
  limits how informative their disagreement can be.

# Rohlik (real data) — Final Results

Single frozen run on the Rohlik **test split** (d_1347–d_1402, 8 Apr – 2 Jun 2024), warehouse
Prague_1, 60 items, 3,360 forecast points at h = 1, plus three rolling-origin backtests. Data: real
daily sales from the Kaggle Rohlik Sales Forecasting Challenge v2, converted by
`retailsense.data.rohlik`. Three agents (Historical, Calendar, Weather); no Trend agent because no
search-interest data exist.
